每个阶段只运行直接相关的必要验证。已经通过的全站测试不反复执行；无关的非阻塞问题先记录，最后集中处理。阻塞、数据安全和破坏性风险及时处理。PC 优先，手机端后续专项完善。保留 Git 提交、数据备份及回滚能力。

## 下一阶段：仅 T 恤商品详情弹窗

参考页面为 `https://netprosourcing.vercel.app/shop.html?category=clothing`。**Clothing 是包含多种服装款式的分类，不能把整个分类或商品列表改造成 T 恤定制页。** 改造位置是点击具体商品后出现的详情弹窗。保留分类、列表、稳定产品编号和各款独立信息；其他服装继续使用现有功能。

启用第一期定制器的 T 恤需要：

1. 仅保留 Custom request，移除 Ready stock 选项并隐藏 Request type 切换。
2. 常用黑、白、灰、红等颜色及自定义色轮，服装预览实时变色。
3. 产品实际支持的完整尺码，按尺码分别填写订购数量。
4. 上传客户定制图案；正面、背面、左袖、右袖等区域按该商品能力配置。
5. 图案可拖动、缩放、旋转并实时显示；各面设计独立保存，切换视角不丢失。
6. 各区域可独立选择刺绣、丝网印刷、热转印等工艺，也可不指定工艺；支持没有图案的基础款。
7. 领口织唛/领标：常见形态选择、上传 Logo、效果预览。
8. 删除该定制流程中的 “What would you like to explore?”，保留 Project note。
9. Add to Bag 保存完整商品配置、原始图案、设计参数及效果图；不能只保存合成缩略图。
10. 购物袋集中提交询价，团队实际收到并能够查看完整定制需求。

每款 T 恤加载各自的商品图片、视角素材、颜色、尺码和区域配置；不能全部使用同一套固定素材。缺少某款的背面或侧面素材时，应明确补齐或禁用对应能力，不能伪造可用预览。

## 后续 Sanity 商品配置的设计边界

以下是下一阶段的数据职责规划，**本阶段不新增这些 Schema、不迁移产品、不实现定制器**。先建立 T 恤所需的最小能力，再扩展，不预先开发所有商品编辑器。

| 配置职责 | 后续应由后台管理的内容 |
| --- | --- |
| 启用与商品类型 | 在线定制开关、实际商品类型、对应编辑模块；不能根据 Clothing 分类或商品标题直接启用全部产品 |
| 预览素材 | 正面、背面、侧面等稳定视角标识与该款独立素材，必要的变色显示素材 |
| 属性 | 该款允许的颜色、自定义颜色能力、尺码、规格及其他实际属性 |
| 区域 | 稳定区域标识、所属视角、可定制位置、范围和尺寸限制 |
| 工艺 | 每个区域允许的工艺及是否可不指定；工艺选项与展示名称分离 |
| 标签 | 是否支持织唛/领标、允许的形态、素材及可上传 Logo 的预览位置 |
| 询价模式 | 是否支持普通询价、定制询价及各自选项；第一期启用的 T 恤仅定制询价，其他商品保持原状 |

配置使用稳定的商品、视角、区域及工艺身份，不随名称或排列变化重建。发布的产品配置应有可追踪版本；已加入购物袋的设计保存当时配置快照，避免后台后续改图或调整区域使客户设计错位。

## 模块与数据分离

- 页面展示、Sanity 公司内容/商品配置、客户定制状态、购物袋和询价传输分别维护，使用明确接口连接。
- T 恤可使用自己的二维编辑器；未来卫衣、Polo、帽子、包袋、徽章可选择适合各自商品的编辑模块，不强制共用同一编辑画布。
- 上传、文件引用、区域设计参数、购物袋快照及询价适配尽量复用；不因首页或 Shop 布局变化重新生成客户设计身份或数据。
- 设计参数应表达区域内的位置、缩放、旋转和层级，独立于当前浏览器像素及 DOM；各视角分开保存。
- 尺码数量及设计、标签、工艺、Project note 均进入完整询价快照；服务端验证产品实际能力和数量，不能只依赖前端校验。
- 保留旧商品、旧购物袋和既有询价数据的兼容路径；新版本数据显式版本化，不把新配置悄悄强塞为旧字段含义。

## 开始定制器前要解决的实际依赖

- 逐款确认 T 恤的视角素材、可变色方案、实际颜色/尺码、定制区域和工艺；不把未确认的业务限制写死。
- 选择适合客户原图、效果图与询价记录的持久存储及权限方案。Sanity 管理网站内容与商品配置，不能直接把客户图案当作公开网站素材发布。
- 现有询价附件限制为最多 3 个文件、合计 2 MB；多区域原图及效果图不能直接沿用该限制。下一阶段需设计兼容的上传/文件引用与邮件摘要方案，确保团队能长期查看完整需求，不依赖很快失效的链接。
- 大文件和图像不得塞进 localStorage；购物袋状态、原图文件和可恢复设计分别处理。具体存储服务、文件格式与保留期限待该阶段确认，不在当前阶段开通服务或引入密钥。
- 验收必须覆盖不同款素材、逐尺码数量、无图基础款、各区域工艺、标签、视角往返、刷新恢复、Add to Bag 和完整询价接收；实际邮件发送需有明确的测试收件人和授权。
